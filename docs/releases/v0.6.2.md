# v0.6.2 — Lower background load during sessions

This release reduces the work that Shizzi and the phone do while a tethering session runs. It includes the v0.6.1 datapath tuning unchanged. Tethering behavior and settings do not change.

## Changes

- **Fewer notification updates.** The session notification used to update once per second, because the traffic totals change every second. Each update made System UI rebuild the notification and the app badge. The notification now updates at once when its title, device count, or message changes. Traffic totals alone update at most every 10 seconds. On a Galaxy A17 (SM-A176U1) with v0.6.1, System UI used about 37% of one core during a session. With v0.6.2 it used about 2%.
- **Device count from Android's client list.** Shizzi counted hotspot devices by reading `dumpsys wifi` every 10 seconds. That report was about 700 KB and took about 0.5 seconds to produce. Shizzi now receives the client list from Android's tethering callback (`TetheringEventCallback.onClientsChanged`). It falls back to `dumpsys wifi` until the first list arrives. With this change and the fewer notification updates, Android's system process (`system_server`) used about 8% of one core during a session, compared with about 17% with v0.6.1. Hotspot traffic was lighter during the v0.6.2 measurement, so this comparison is approximate.
- **One shared thread pool for `dumpsys` output.** The helper used to create a new pool of two threads for each `dumpsys` call, which happened every few seconds. It now reuses one pool.

## Known issues

- With v0.6.1, the helper used about 40% of one core at about 140 KB/s of hotspot traffic. Most of that time was in the Go runtime scheduler inside the datapath, and in the watchdog's `dumpsys tethering` check every 5 seconds. This release does not change either one.
- Android's client list counts devices that hold a DHCP lease. A device with a static address, or with IPv6 only, may not be counted.

## Install

Download `shizzi-unified-v0.6.2-release.apk` from the release page and install it over v0.6.1 with `adb install -r`, or open it on the phone. It is signed with the same key as v0.6.1, so it updates an existing install and keeps its pairing.

The running helper keeps its old code after the update, because the helper's interface did not change. To load the new code, stop all protection in Shizzi and start the helper again, or restart the phone.
