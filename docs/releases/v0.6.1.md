# v0.6.1 — Lower background load during sessions

This release reduces the work that Shizzi and the phone do while a tethering session runs. Tethering behavior and settings do not change.

## Changes

- **Fewer notification updates.** The session notification used to update once per second, because the traffic totals change every second. Each update made System UI rebuild the notification and the app badge. The notification now updates at once when its title, device count, or message changes. Traffic totals alone update at most every 10 seconds. On a Galaxy A17 (SM-A176U1), System UI CPU use during a session fell from about 37% of one core to about 1.5%.
- **Device count from Android's client list.** Shizzi counted hotspot devices by reading `dumpsys wifi` every 10 seconds. That report was about 700 KB and took about 0.5 seconds to produce. Shizzi now receives the client list from Android's tethering callback (`TetheringEventCallback.onClientsChanged`). It falls back to `dumpsys wifi` until the first list arrives. With this change and the fewer notification updates, Android's system process (`system_server`) CPU use during a session fell from about 17% of one core to about 8%.
- **One shared thread pool for `dumpsys` output.** The helper used to create a new pool of two threads for each `dumpsys` call, which happened every few seconds. It now reuses one pool.

## Known issues

- The helper still uses about 40% of one core at about 140 KB/s of hotspot traffic. Most of that time is in the Go runtime scheduler inside the tunnel datapath, and in the watchdog's `dumpsys tethering` check every 5 seconds. Limiting Go to two cores did not reduce it, so this release does not include that change.

## Install

Download `shizzi-unified-v0.6.1.apk` from the release page and install it over v0.6.0 with `adb install -r`, or open it on the phone. It is signed with the same key as v0.6.0, so it updates an existing install and keeps its pairing.
